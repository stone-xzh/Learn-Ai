> 示例笔记：这里提供的是一个记录模板，并不是已经完成的个人实验或性能结论。

## 先写目标，再运行代码

用一句话描述这次想验证的内容。比如：“修改输入的表达方式，观察输出是否改变。”把预期写在运行之前，有助于区分最初的猜想和后来的观察。

## 记录最少但足够的信息

每次实验至少保存：

1. **环境**：工具、模型与依赖版本。
2. **输入**：使用的数据或文本。
3. **变量**：这次主动改变了什么。
4. **结果**：实际输出，而不仅是“成功”或“失败”。
5. **解释**：观察支持了什么，还有哪些其他解释。

下面是一段只使用 Python 标准库的记录示例：

```python
import json
from pathlib import Path

record = {
    "question": "这次实验想回答什么？",
    "input": "在这里记录输入",
    "change": "本次调整的条件",
    "observation": "在这里填写实际观察",
    "next_step": "下一步要验证什么？"
}

Path("experiment.json").write_text(
    json.dumps(record, ensure_ascii=False, indent=2),
    encoding="utf-8"
)
```

## 给结论标注边界

一次实验只代表当时的条件。记录样本数量、尝试次数和异常结果，可以让之后的自己判断这条结论还能用在哪里。

**保留意外的结果，往往比写出一个漂亮的结论更有用。**
